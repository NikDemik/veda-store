# Импорт собранного каталога VEDA

Обновление 16 октября 2026: по запросу пользователя документы VEDA CST удалены из активных данных и БД. Удалены 788 привязок к товарам, 12 привязок к сериям и 2 записи CatalogAsset, очищены 630 JSON файлов, 643 ProductSource и 10 снимков серий. В каталоге остаётся 201 уникальный файл. Числа 203 файла и 1,34 ГБ ниже описывают первоначальную загрузку. Исходные HTML и физические файлы в кэше/хранилище сохранены; их ссылки больше не входят в каталог.

Повторная очистка: `node prisma/remove-veda-cst.mjs --apply`; без --apply выполняется только планирование. Повторный сбор и импорт соблюдают общее правило исключения `src/config/catalogDocumentPolicy.mjs`. Изменённые файлы этого этапа: это правило, скрипт очистки, `content/collect-drives.mjs`, `content/verify-content.mjs`, `content/README.md`, `prisma/import-veda-content.mjs`, `prisma/verify-veda-import.mjs`, JSON товаров/серий и результаты проверки content.

Проверки удаления: повторный план не находит записей VEDA CST; нормализация всех 929 товаров, проверка content по исходным HTML и хешам, TypeScript и production build прошли. Проверка кодировки охватила 951 файл. Полная историческая сверка импортера --verify ожидает DRAFT и останавливается на уже опубликованных ACTIVE; статусы товаров при удалении документов не изменялись.

## Выполненная загрузка

16 октября 2026 года миграция `20261016120000_veda_catalog_content` применена к локальной MySQL 8.0.30, БД `veda_shop`. До загрузки в каталоге не было товаров, категорий, брендов или серий.

Импортированы:

- 929 товаров в статусе DRAFT, без публикации;
- 13 серий/исполнений и родительская серия VF-101;
- категории ПЧ, инверторных модулей, панелей оператора и плат расширения с общим родителем;
- бренд VEDA и четыре типа товаров: 837 ПЧ, 86 инверторов, 4 панели оператора и 2 платы расширения; использована существующая единица `pcs`;
- 939 принадлежностей к сериям: 10 SKU относятся к двум сериям;
- 16 046 строк основных характеристик, включая повторяющиеся названия и порядок;
- 952 уникальных снимка страниц; полные JSON сохраняют все дополнительные контексты sourceVariants. Всего исходные JSON содержат 16 284 строки характеристик с учётом повторных контекстов;
- 258 наборов параметров нагрузки: три режима у каждого из 86 инверторов VF-400;
- 203 уникальных физических файла по SHA-256, ссылки на них у товаров и серий.

Цены «без НДС» пересчитаны через Prisma.Decimal с НДС 22%, округление до копеек HALF_UP. Пример: ABC00201, 56 963,40 без НДС → 69 495,35 с НДС. Исходные цены/пометки сохраняются в ProductSource. У 24 товаров без числовой цены установлены priceOnRequest=true, price=0, isSellable=false. Наличие «на складе» без количества не превращается в придуманный остаток: stockQty=0, исходный текст сохранён.

Изначально файлы зарегистрированы с оригинальными HTTPS-ссылками drives.ru и пустым storageKey. После явного разрешения пользователя все 203 файла, 1 336 640 603 байта, перенесены в настроенное Yandex Object Storage, ссылки в БД обновлены. Размер и metadata.sha256 проверены через HEAD для каждого файла. Локальные оригиналы в content/assets сохранены. Публичная доступность перенесённого файла дополнительно проверена без авторизации: HTTP 200 и ожидаемый Content-Length.

Для оригинальных изображений в next.config.ts разрешён только HTTPS-хост drives.ru и путь `/wa-data/public/shop/**`. Черновики теперь закрыты по прямому URL и в метаданных товара: оба запроса требуют status=ACTIVE. Заказ черновиков и товаров с ценой по запросу также блокируется сервером.

Детальный локальный отчёт последнего успешного импорта: `storage/catalog-imports/veda-content-import-report.json`. Этот runtime-файл содержит количества и ID товаров, не содержит паролей и не предназначен для Git.

## Команды

Все команды выполняются из корня проекта и используют DATABASE_URL из .env.

```sh
npx prisma migrate deploy
npm run prisma:generate
node content/verify-content.mjs
npm run test:veda-import
npm run prisma:import-veda -- --plan
npm run prisma:import-veda -- --apply
npm run prisma:import-veda -- --verify
```

Без аргументов выполняется только планирование. `--apply` создаёт отсутствующие товары, регистрирует файлы по оригинальным URL и выполняет полную проверку импорта; сетевой отправки файлов нет. Повторный запуск с тем же набором не дублирует товары, связи и файлы. При существующем SKU без соответствующих снимков или при изменившемся источнике скрипт останавливается до записи: он не предназначен для перезаписи вручную отредактированного каталога. Товары, отсутствующие в источнике, не удаляются.

`--verify` сопоставляет товары с исходными данными: тип, категорию, DRAFT, цену, налоговую ставку, доступность, остатки, модель, характеристики, нормализованные атрибуты, режимы нагрузки, серии, изображения, документы и JSON снимков. Проверка рассчитана на состояние сразу после импорта: после ручной публикации или изменения цены ожидаемо потребуется отдельная сверка.

## Перенос файлов в объектное хранилище

Только после отдельного разрешения на передачу файлов:

```sh
npm run prisma:import-veda -- --apply --upload-assets
```

Используются существующие YANDEX_STORAGE_* настройки. Перед загрузкой проверяются локальный размер и SHA-256. Объекты размещаются по устойчивому ключу `catalog/veda/sha256/<hash>.<ext>`, файлы свыше 64 МиБ загружаются частями по 16 МиБ. Уже загруженные файлы проверяются через HEAD по размеру и metadata.sha256. Неудачная multipart-загрузка прерывается; последующий запуск переиспользует завершённые объекты.

После загрузки URL и storageKey обновляются в CatalogAsset, ProductImage/ProductDocument и основных изображениях товаров/серий/категорий. Товары повторно не создаются. Снимки источников остаются исходными. Операции выполняются по файлам и товарам, а не одной общей транзакцией: при сбое уже завершённые записи сохраняются, повторный запуск продолжает работу. Удаление файлов из content и чужих объектов хранилища не выполняется.

## Что ещё не внедрено

Публикация, полный интерфейс новых полей в админке, фильтры VF-400 и пагинация остаются отдельными задачами из `docs/veda-catalog-schema-audit.md`. В частности, текущая админка показывает только 200 последних товаров; наличие остальных в БД проверяется импортным скриптом. Импорт не превращает собранные товары в готовый к публикации каталог без редакторской проверки.

Файлы реализации: `prisma/import-veda-content.mjs`, `prisma/verify-veda-import.mjs`, `src/data/catalog/veda-import.mjs`. Нормализация проверяется по всему набору и отдельным примерам цен, статусов, аксессуаров, размеров и режимов VF-400. Дополнительно проверены повторное применение, согласованность БД и актуальность миграций. TypeScript и production build прошли; на запущенной production-сборке проверены 404 для черновика по прямому URL и HTTP 200 для каталога и категории.

## Изменённые файлы этапа импорта

- `prisma/import-veda-content.mjs` — планирование, загрузка в БД, перенос файлов и сверка.
- `prisma/verify-veda-import.mjs` — проверки преобразований по всему набору.
- `src/data/catalog/veda-import.mjs` — категории, типы, атрибуты и режимы нагрузки.
- `package.json` — команды импорта и проверки.
- `next.config.ts` — разрешённый источник оригинальных изображений для режима без внешней отправки.
- `src/components/pages/shop/product-page.tsx` — защита черновиков по прямому URL.
- `src/app/(shop)/product/[slug]/page.tsx` — та же защита для метаданных.
- `docs/veda-content-import.md` — результаты, команды и ограничения.
- `docs/veda-catalog-schema-audit.md` — актуализация статуса миграции и импорта.

Схема и SQL-миграция подготовлены на предыдущем этапе; в этом этапе миграция применена без изменения её SQL. Скрипт проверки content обновил время проверки в `content/verification-report.json` и `content/inventory.md`.
