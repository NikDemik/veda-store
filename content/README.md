# Каталог VEDA VF: сбор с drives.ru

Источник структуры: https://drives.ru/category/veda/

Раздел: https://drives.ru/category/veda/preobrazovateli-chastoty-veda-vfd/

Дополнительно собираются модульные решения VF-400: https://drives.ru/category/veda/modulnye-resheniya/

Собрано 16 октября 2026 года. Все результаты и скрипты находятся в этой папке. Сбор не изменяет сайт или базу данных проекта.

## Результат

Охват: VF-11, VF-51, VF-500, VF-302L, VF-302C, исполнения VF-101 STO/HBC/DBC/AQUA/Basic/FireMode/Rod Pump и VF-400. Точные количества по сериям и результаты последней успешной проверки находятся в `verification-report.json` и `inventory.md`. Актуальный перечень карточек — `products/index.json`.

Число файлов считается по уникальным URL; некоторые изображения по разным URL имеют одинаковое содержимое. Разные исполнения VF-101 хранятся в отдельных папках, например `products/VF-101-HBC/`.

В каталог включены инструкции, листовки, каталоги, сертификаты, чертежи PDF/DWG, 3D-модели и схемы выбранных серий. По запросу пользователя документы VEDA CST исключены из JSON товаров/серий и БД, включая вложенные снимки sourceVariants. Правило `src/config/catalogDocumentPolicy.mjs` применяется при сборе, проверке и импорте. Общие документы сохраняются один раз, JSON товаров ссылаются на них. Исходные HTML и кэш скачанных файлов сохраняют материалы источника.

## Структура папки

- `collect-drives.mjs` — парсер, загрузка HTML и файлов, формирование JSON и отчёта.
- `verify-content.mjs` — автономная проверка результатов по сохранённым HTML, размерам и SHA-256.
- `catalog-structure.json` — дерево категории «Низковольтные ПЧ и УПП», включая дочерние разделы и ссылки.
- `series/*.json` — описание серии или исполнения, документы, изображение и обнаруженные URL товаров.
- `products/index.json` — общий список артикулов с типовыми кодами и путями JSON.
- `products/<серия>/*.json` — отдельный JSON для каждого артикула.
- `assets/documents/`, `assets/images/` — скачанные оригинальные файлы по опубликованным ссылкам. Рядом с каждым файлом находится JSON с URL, размером, MIME-типом, временем загрузки и SHA-256.
- `raw/pages/*.html` — исходные страницы без преобразования; соответствующий URL указан в поле `source` JSON товара, серии или структуры.
- `collection-report.json` — полнота обхода, ошибки загрузки, предупреждения источника, размер данных.
- `verification-report.json` — итог последней успешной проверки.
- `inventory.md` — сводка успешной проверки по всем сериям.
- `discovery/*.json`, `discovery-report.json` — результаты необязательного предварительного обхода без скачивания файлов.

Все локальные пути внутри JSON заданы относительно `content/`. Для изображений используется большая версия, опубликованная в галерее карточки (`970`), а не миниатюры; это не обещание полного разрешения исходной фотографии.

## Формат товара

`sku` — артикул, `model` — значение «Типовой код» из характеристик, `seriesId` — серия, `categoryPath` — путь категории. `title`, `description` и `descriptionHtml` сохраняют контент карточки; HTML является материалом источника и требует очистки перед отображением на сайте.

`characteristics` — массив всех строк полной вкладки характеристик, включая повторы. Названия, единицы в названиях и значения сохраняются без пересчёта; нормализуются только пробелы. Это все характеристики, опубликованные в карточках; таблицы внутри PDF автоматически в этот массив не переносятся.

`images` и `documents` содержат `sourceUrl`, `localPath`, `bytes`, `sha256`, `contentType`, `downloadedAt`. Документы серии, добавленные к карточке, имеют `inheritedFrom`. `source` содержит URL карточки, путь исходного HTML, его SHA-256 и время сбора. `price` и `availability` — снимок сведений на момент загрузки, цены сохранены исходным текстом с пометкой НДС.

Если у товара отсутствует собственное фото и сайт показывает заглушку `dummy`, заглушка не скачивается. Вместо неё используется доступное изображение серии с `inheritedFrom` и предупреждением `no-product-image`. Это не индивидуальная фотография артикула. При отсутствии изображения серии массив остаётся пустым с тем же предупреждением.

Если один артикул встречается в нескольких сериях, индекс хранит массив `seriesIds`; файл товара остаётся один.

Если у одного артикула есть разные страницы, первая сохраняется основным снимком, остальные — в `sourceVariants` со своими характеристиками, описаниями, документами и изображениями. Поле `sourceUrls` индекса перечисляет все страницы. В отчёте количество страниц и уникальных артикулов указывается отдельно.

Карточки без опубликованных характеристик сохраняются с пустым массивом и предупреждением `no-characteristics`. Например, в списке VF-500 присутствуют пульты PBN00001 и PBN00002 с такими карточками. Пропущенные сведения вручную не добавлялись. Для ссылки документа без расширения расширение сохранённого файла определяется по сигнатуре архива/PDF.

## Найденные особенности источника

- У 9 карточек VF-11 в заголовке отсутствует суффикс `-B-H`, который присутствует в поле «Типовой код». В `model` сохранён код из характеристик; обе версии доступны в JSON, расхождение отмечено в `warnings`.
- В карточках повторяется характеристика «Панель оператора». Строки сохранены и отмечены в `warnings`.
- Три PDF VF-51 начинаются с пробела перед `%PDF-`. Парсер принимает такой заголовок и сохраняет байты без изменений.
- В категории VF-51 обнаружены ABA00002–ABA00014. ABA00001 в списке источника отсутствует; отдельная карточка для него не создавалась.

## Повторный запуск

Из корня проекта, с установленными зависимостями проекта и Chromium для Playwright:

```sh
node content/collect-drives.mjs
node content/verify-content.mjs
```

Для предварительного определения артикулов и страниц без скачивания документов и изображений: `node content/collect-drives.mjs --discover-only`.

Обычный запуск использует сохранённые страницы и проверенный кэш файлов. Для обновления с сайта:

```sh
node content/collect-drives.mjs --refresh
node content/verify-content.mjs
```

Парсер проверяет HTTP-ответы, размеры, сигнатуры PDF/ZIP/RAR/изображений, выполняет повторные попытки при сетевых ошибках, обходит обнаруженные ссылки пагинации, отлавливает дубли артикулов и возвращает ненулевой код при ошибках. Существующие посторонние файлы и результаты прежних запусков автоматически не удаляются; актуальный перечень находится в `products/index.json`.

Проверка сопоставляет все строки характеристик и ссылки галерей/документов с сохранёнными HTML, проверяет файлы по размеру и SHA-256, кодировку JSON и соответствие числа собранных товаров числу обнаруженных. В исходных страницах скрипты сайта не исполняются.

Проверки проекта при подготовке: `npm run typecheck` и `npm run build` завершились успешно.
